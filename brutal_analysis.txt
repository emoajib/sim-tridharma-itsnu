BRUTAL MODE ANALYSIS: Sistem Multi-Agent AI Akreditasi

1. Inti masalah sebenarnya
Codebase terstruktur sebagai monolitik dengan ketergantungan sirkular yang ekstrem antara Laravel (PHP) dan AI Agents (Python). Controllers langsung menginstantiasi service melalui app() helper tanpa dependency injection, creando ketergantungan ketat yang mengujil testing dan mantenability. Tidak ada lapisan abstraksi antara application logic dan infrastruktur MCP, yang menyebabkan duplikasi kode dan violasi paruh prinsip clean architecture.

2. Analisis mendalam
- Controllers (seperti PrediksiController dan IntegrasiController) langsung memanggil MCPClientService melalui app(MCPClientService::class), yang merupakan service locator pattern yang dianggap anti-pattern
- MCPClientService berisi 581 baris kode dengan tanggung jawab yang terlalu luas: HTTP client wrapper, MCP protocol handler, tool executor, fallback manager, dan caching layer - semua dalam satu kelas
- Tidak ada interface yang mendefinisikan kontrak antara layanan dan penggunaannya, membuatnya impossible untuk mengganti implementasi atau melakukan mock dalam unit test
- Business logic tersebar di controllers (validasi request), service (pemanggilan MCP), dan agent tools (Python) tanpa pemisahan yang jelas
- Duplikasi terlihat dalam cara menangani respons MCP (extractToolMethod yang kompleks dipakai berkali-kali) dan pola try-catch yang seragam di setiap method publik

3. Blind spot yang jarang disadari
Tim terkialang dengan kemudahan pemanggilan layanan melalui app() helper dan tidak menyadari bahwa ini menciptakan hidden dependencies yang tidak terdeteksi oleh static analysis tools. Setiap controller yang menggunakan app(MCPClientService::class) secara implicit mengandalkan:
- Konfigurasi MCP yang valid di file .env
- Layanan AI Agents berjalan dan dapat diakses di localhost:8001
- Layanan RAG berjalan dan dapat diakses di localhost:5001
- API Key yang properly configured
Hal ini menyebabkan kegagalan runtime yang tidak terdeteksi sampai produksi, dan membuat aplikasi sulit dijalankan dalam isolasi untuk pengembangan atau testing.

4. Strategi terbaik
Implementasi Dependency Injection dengan interface yang jelas untuk semua layanan eksternal. Buat abstraksi layer yang memisahkan:
- Application Contracts (interface yang mendefinisikan apa yang diperlukan)
- Infrastructure Implementations (konkret implementation yang menangani detail teknis)
- Application Services (use case/orchestrator yang menggunakan kontrak)
- Controllers (hanya menangani HTTP concern)

Spesifik untuk MCP, buat interface seperti:
interface AgentService {
    public function runPrediksiSkor(int $prodiId, ?int $periodeId): array;
    public function runIntegrasiSync(string $sumber): array;
    // ... other methods
}

5. Langkah eksekusi paling efektif
Langkah pertama yang harus dilakukan: Refaktor PrediksiController dan IntegrasiController untuk menggunakan constructor injection bukannya service locator.

Ubah dari:
public function runAgent(Request $request) {
    $mcpClient = app(MCPClientService::class);
    // ...
}

Menjadi:
private AgentService $agentService;
public function __construct(AgentService $agentService) {
    $this->agentService = $agentService;
}
public function runAgent(Request $request) {
    $result = $this->agentService->runPrediksiSkor($prodiId, $periodeId);
    // ...
}

Daftarkan binding di AppServiceProvider:
$this->app->bind(AgentService::class, MCPClientService::class);

6. Kesalahan fatal yang harus dihindari
JANGAN mencoba untuk refaktor seluruh codebase sekaligus. Ini akan menyebabkan:
- Merge conflicts yang kompleks
- Regression yang tidak terdeteksi
- Tim terdistraksi dari fitur yang sebenarnya diperlukan
- Potensi introduksi bug baru yang mengancam stabilitas

Fokus hanya pada dua controller yang paling kritik dan berbahaya (PrediksiController dan IntegrasiController) karena mereka merupakan entry point utama untuk fungsi AI yang merupakan inti nilai sistem ini.

7. Optimasi level expert
Setelah DI terimplementasi, tambahkan decorator pattern untuk cross-cutting concerns seperti:
- LoggingDecorator yang otomatis log semua panggilan layanan
- CachingDecorator yang menangani caching hasil berdasarkan parameter
- RetryDecorator yang mengimplementasikan exponential backoff untuk layanan yang tidak stabil
- CircuitBreakerDecorator yang mencegah cascade failure ketika layanan Agent down

Ini akan membuat kode lebih bersih karena masing-masing concern terpisah, dan memperluas fungsi tanpa mengubah inti layanan.

8. Kesimpulan akhir
Masalah struktural utama adalah ketergantungan ketat melalui service locator pattern yang menghalangi testability, maintainability, dan skalabilitas. Perbaikan pertama yang harus dilakukan adalah mengimplementasikan Dependency Injection dengan interface untuk AgentService pada PrediksiController dan IntegrasiController. Ini akan memberikan foundation yang solid untuk perbaikan arsitektur lebih lanjut tanpa mengganggu fungsi existente, dan langsung meningkatkan kualitas kode dengan menghilangkan satu dari dua anti-pattern paling berbahaya dalam codebase ini.
