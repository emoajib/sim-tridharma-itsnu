================================================================================
Sistem Multi-Agent AI untuk Manajemen Tridharma Guna Optimalisasi Akreditasi ITSNU Pekalongan
================================================================================
File ini berisi spesifikasi lengkap untuk membangun aplikasi web sesuai kebutuhan
akreditasi IAPS 4.0 dan IAPT 3.0. Gunakan sebagai acuan tunggal (single source of truth)
seluruh tim pengembang.

================================================================================
1. RINGKASAN EKSEKUTIF
================================================================================
Sistem informasi terintegrasi berbasis role-based access control (RBAC) dan multi-agent AI
yang mengelola data Tridharma dosen, sarpras, keuangan, kerjasama, mahasiswa, dan alumni.
Dilengkapi dashboard analitik prediktif untuk Kaprodi, Dekan, Rektor, LPM, LPPM, dan
Lembaga Kerjasama. Agent AI bertugas verifikasi otomatis, deteksi anomali, rekomendasi
perbaikan akreditasi, dan generasi dokumen LED/LKPT secara cerdas.

Tujuan: Mempercepat persiapan akreditasi, menjaga konsistensi data, notifikasi proaktif,
mencapai predikat UNGGUL atau BAIK SEKALI.

================================================================================
2. ARSITEKTUR AGENT AI
================================================================================
Sistem menggunakan 6 agent AI yang berkolaborasi via message broker (RabbitMQ).

| Agent               | Fungsi                                                                 | Algoritma / Model                          |
|---------------------|------------------------------------------------------------------------|--------------------------------------------|
| Verifikasi Data     | Memeriksa keabsahan bukti (file vs klaim), deteksi duplikasi, inkonsistensi | Rule-based + NLP ringan (metadata file)    |
| Prediksi Skor       | Menghitung skor sementara & prediksi akhir akreditasi                  | Weighted Sum Model + Monte Carlo Simulation|
| Rekomendasi Tindakan| Memberi saran perbaikan personal per prodi/dosen                       | Decision Tree + Association Rules (Apriori)|
| Peringatan Dini     | Memantau threshold indikator, kirim notifikasi real-time               | Rule-based + Isolation Forest (anomali)    |
| Generator Dokumen   | Menyusun LED/LKPT otomatis sesuai template BAN-PT/LAM                  | Template + LLM (Gemini API / Llama 3 lokal)|
| Integrasi Eksternal | Sinkronasi otomatis dengan PDDikti, SINTA, Sister, atasi konflik       | CRON + Reconciliation logic (majority voting) |

Komunikasi: Publish-subscribe via RabbitMQ. Agent dapat berjalan asinkron.

5. DASHBOARD ANALITIK DENGAN AGENT AI (PER ROLE)
================================================================================
Setiap dashboard memiliki widget Agent AI:
- Skor akreditasi simulasi (agent prediksi)
- Daftar kekurangan (agent verifikasi)
- Rekomendasi prioritas (agent rekomendasi)
- Alert merah/kuning (agent peringatan)

Komponen visualisasi:
- Gauge chart untuk skor prediksi
- Radar chart capaian per kriteria (C1-C9)
- Bar chart perbandingan capaian vs target
- Trend line (publikasi, PkM, kerjasama) dengan linear regression

Fitur interaktif:
- Drill-down klik pada kriteria -> tampilkan bukti & indikator kurang
- Filter periode akademik (semester/tahun)
- Tambah mode bandingkan antar prodi (untuk dekan/rektor)
- Tombol "Generate LKPT/LED dengan AI" memanggil Agent Generator

Mockup UI terdapat di bagian akhir (lihat poin 10).

6. STACK TEKNOLOGI LENGKAP (SIAP PRODUKSI)
================================================================================
Backend utama: Java 21 + Spring Boot 3.2  atau  PHP 8.2 + Laravel 11 (pilih sesuai tim)
Agent AI microservice: Python 3.11 + FastAPI + Celery
Database: PostgreSQL 16 + TimescaleDB (time-series agent log) + pgvector (semantic search bukti)
Cache & Queue: Redis 7 + RabbitMQ 3.13
Frontend: React 18 + Vite + Tailwind CSS + shadcn/ui
Visualisasi: Apache ECharts 5.5
Orkestrasi: Docker + Kubernetes (k3s) atau docker-compose untuk staging
Integrasi eksternal: Feeder PDDikti (SOAP), SINTA REST API, Sister API
LLM (opsional): Gemini 1.5 Flash (cost rendah) atau Llama 3 8B (inference lokal)
Logging & Monitoring: ELK Stack (Elasticsearch, Logstash, Kibana) + Prometheus + Grafana

Persyaratan kepatuhan:
- SSL/TLS untuk semua koneksi (HTTPS)
- JWT dengan refresh token untuk autentikasi
- Backup harian database ke S3/minIO
- Log audit untuk semua perubahan data kritis (tabel logging terpisah)

7. UML RINGKAS (CUKUP UNTUK CODING)
================================================================================
7.1 Use Case (aktor: manusia + agent AI)
- Dosen: Input portofolio, upload bukti, lihat BKD, tanya asisten AI
- Kaprodi: Semua use case dosen (untuk prodi) + dashboard analitik + generate LKPT
- Dekan: Dashboard agregat fakultas, perbandingan prodi, rekap BKD
- Rektor: Dashboard institusi, skor prediksi, kebijakan strategis
- LPM: Kelola audit, risk register, generate LED institusi
- LPPM: Verifikasi penelitian/PkM, sinkronasi SINTA
- Kerjasama: Kelola mitra, MOU, realisasi
- Agent AI: (otomatis) verifikasi data, update prediksi, kirim alert, generate dokumen

7.2 Class Diagram (Entity inti + Agent interface)
@Entity: Dosen, Prodi, KegiatanTridharma, BuktiDokumen, IndikatorAkreditasi, PemenuhanIndikator, SkorAkreditasi, dll.
Interface Agent { void execute(Task task); }
Implementasi: VerifikasiAgent, PrediksiAgent, RekomendasiAgent, PeringatanAgent, GeneratorAgent, IntegrasiAgent.
Scheduler: @Scheduled(fixedDelay=3600000) untuk menjalankan agent periodik.

7.3 Sequence Diagram (Prediksi otomatis)
AgentScheduler -> PrediksiAgent: run()
PrediksiAgent -> DB: ambil data capaian semua prodi
DB --> PrediksiAgent: data
PrediksiAgent -> WeightedSumModel: hitung skor
Model --> PrediksiAgent: skor + confidence interval
PrediksiAgent -> DB: simpan ke table agent_prediction_history
PrediksiAgent -> MessageBroker: publish event "skor_update"
MessageBroker -> WebSocket: kirim ke frontend
Frontend -> User: render skor baru di dashboard

================================================================================
8. FITUR AGENT AI YANG PALING KRUSIAL UNTUK AKREDITASI
================================================================================
8.1 Auto-checklist pemenuhan indikator
   - Agent Verifikasi mencocokkan data & bukti dengan master indikator akreditasi (IAPS/IAPT)
   - Output: tabel status hijau/kuning/merah per butir

8.2 Prediksi kelulusan akreditasi
   - Agent Prediksi menggunakan Weighted Sum + Monte Carlo (1000 simulasi)
   - Output: Probabilitas Unggul/Baik Sekali/Baik/Tidak terakreditasi

8.3 Rekomendasi strategis prioritas
   - Agent Rekomendasi menganalisis gap terbesar (selisih capaian vs target)
   - Output: "Tingkatkan publikasi internasional: kurang 3 artikel", "Rasio dosen S3 28% perlu tambah 2 dosen"

8.4 Otomatisasi narasi LED/LKPT
   - Agent Generator dengan LLM (prompt engineering)
   - Input: data tabel capaian prodi + template BAN-PT
   - Output: dokumen .docx dengan paragraf narasi, tabel, grafik siap edit

8.5 Deteksi anomali BKD
   - Agent Peringatan bandingkan beban dosen dengan rata-rata fakultas, threshold 20% di bawah rata-rata
   - Notifikasi ke Kaprodi jika dosen < 12 SKS dua semester berturut-turut

9. RENCANA IMPLEMENTASI (5 FASE, TOTAL 25 MINGGU)
================================================================================

   - Setup infrastruktur (Docker, PostgreSQL, Redis, RabbitMQ, MinIO)
   - Inisialisasi skeleton backend (Spring Boot/Laravel) dan frontend (React)

Fase 4 (4 minggu) - Dashboard Analitik + LLM Generator:

   - User acceptance test (minimal 5 kaprodi, 10 dosen, 3 pimpinan)
   - Pelatihan dan dokumentasi
   - Deployment produksi (K3s + backup otomatis)

Catatan: Tim minimal 5 orang (1 TL, 2 backend, 1 frontend, 1 AI engineer).

12. INSTRUKSI KEPATUHAN BUILD APLIKASI WEB
================================================================================
Agar pembangunan aplikasi sesuai dengan blueprint ini, tim pengembang WAJIB:

12.1 Mengikuti arsitektur yang telah ditetapkan (tidak mengubah modul inti tanpa persetujuan).

12.2 Mengimplementasikan seluruh 45 tabel database sesuai ERD, minimal kolom yang disebut.
     Tabel log agent (32-37) wajib ada untuk audit trail AI.

12.3 Menyediakan REST API dokumentasi menggunakan OpenAPI (Swagger) untuk backend.

12.4 Mengintegrasikan agent AI sebagai microservice terpisah (Python) dan berkomunikasi via
     RabbitMQ (publish event) dan REST API (trigger langsung).

     permission-nya; password hash bcrypt; gunakan HTTPS.

12.7 Mengimplementasikan scheduler (cron) untuk menjalankan agent prediksi, verifikasi, dan
     integrasi setiap 1 jam (minimum).

12.8 Menyediakan fitur ekspor dokumen (PDF, DOCX) untuk LED/LKPT dan dashboard.

12.9 Melakukan uji coba (UAT) dengan minimal 5 pengguna dari masing-masing role utama
     (Dosen, Kaprodi, Dekan, Rektor, LPM).
